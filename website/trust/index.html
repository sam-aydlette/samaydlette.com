Trust Center

samaydlette.com

This system is built to adhere to the FedRAMP 20x Class C Certification requirements at the Moderate impact level. It is a self-attested proof of concept: it is not FedRAMP Certified, has no agency sponsor, and has not been assessed by a third party.

The page is written from the seat of an Authorizing Official: the person at an agency who would decide whether to rely on a system like this one. You are probably not one, and no agency has been asked to rely on this system; if you are an AO, welcome. Either way, the sections below walk through the questions an AO would ask, in the order they would ask them, so you can judge the answers for yourself.

      8 Certification data, access and sharing

      This section is plain HTML: it reads the same with JavaScript off.

      All the certification data, in one index

      The signed trust manifest (readable version) lists every piece of FedRAMP certification data this trust center shares: its URL, media type, update cadence, signature and signer, and its human-readable forms. Every JSON artifact has a complete readable view (.view.md) that the build checks reproduces the JSON exactly, and the policies and procedures are served as Markdown from the policy and procedure index. Fetch anything with a plain HTTPS GET; no account or key is needed. The assessor guide says how to check each FedRAMP rule and KSI yourself.

      Availability is measured from outside AWS, by a monitor on GitHub Actions that publishes to GitHub: current and 30-day availability, with incidents. It stays readable when this site is not.

      Independent assessment (simulated)

      No FedRAMP Recognized assessor has assessed this system. To show the assessor port working end to end, every deploy is assessed by Totally Real Assessment Services, LLC (simulated), which is a GitHub Actions workflow in this repository wearing a lanyard. It re-runs the checks in the assessor guide and signs its results under its own workflow identity: simulated-assessment.json. Its findings appear, verbatim, in the Security Decision Record. It is not independent, and it is not a FedRAMP assessment.

      Request access

      Everything is already public, so an agency can obtain the whole certification package without asking. An agency that wants to be on record, counted in the access inventory and told of changes, can file the agency access form, or write privately to the security contact in security.txt. Name agencies and systems, never people. The same form withdraws a record, and FedRAMP can use it to request the inventory. If a request is ever denied, FedRAMP is told within 5 business days. The procedure is Agency Access to the Certification Package; it is exercised on every deploy with plainly fictional agencies (the exercise log).

      What is shared, and why it is safe to share

      The package is public because this proof of concept holds no federal data and exists to show its evidence. What is never published (account IDs, secrets, personal email addresses, IAM user names, raw logs, the people behind an access request), what is published on purpose, and the determination that publishing it is not likely to harm the system are in the information sharing and disclosure standard.

      Access logging and your privacy

      FedRAMP asks trust centers to log access to certification data and keep summaries of it. This is what this site logs, and what it does not.

      • What is logged. For each request to the site, the CDN records the date and time, the edge location and country it was served from, the method, the path, the response status, the bytes sent and whether it came from cache. It does not record your IP address, user agent, referrer, cookies or query string: those fields are switched off at the edge, so they are never stored.
      • Why. To show, in aggregate, how the certification data under /.well-known/ and this trust center are used, as FedRAMP requires.
      • How long. The raw records are deleted after 90 days. Only monthly counts (per artifact, per response class, per country) are kept, for 13 months, and published at /.well-known/access-summary.json (readable version). Requests to other pages of the site are not counted.
      • Who can see the raw records. Only the operator and the deploy pipeline’s read-only role, in an encrypted bucket that is not public.
      • Agencies. An agency is identified only by what it states in its own access request. Nothing is inferred from network addresses, which are not logged.
      • Your own records. You can ask for the summaries and for the records of your own requests, identified by the times and paths you give (the records hold nothing that identifies a requester). Write to the security contact in security.txt; the answer comes within 10 business days.
