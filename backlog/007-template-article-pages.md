Diagnosed 2026-08-25 during the cleanup review (PR #306), recorded as out of scope there.

The duplication is the largest single quality-of-life cost in the repo and the lowest-risk to fix, but it is only low-risk if the byte-equality discipline above is kept. The head, nav and footer are copy-pasted into all 28 files; changing a nav link today is a 28-file `sed`, and the cache-busting tooling is a workaround for the same root cause.

Suggested order, two commits in one PR so the mechanical half is reviewable by ignoring it:

1. Write the generator and a template. Prove it reproduces the current tree byte-for-byte, except for the differences you can enumerate — resolve the 2-head / 3-footer variance here, deliberately, and record in the commit message which variant won and why.
2. Only then make the actual improvement (single-source nav), and fold cache-busting into the generator — stamping `?v=` at render time — before removing `update-cache-version.js`, `CACHE-BUSTING.md`, and the workflow step that invokes them, in that order.

Worth knowing: this is the only remaining item from the cleanup review that touches published content rather than pipeline plumbing, so it is the one most likely to produce a large, noisy diff in the KSI signal. Land it when the tree is quiet.
